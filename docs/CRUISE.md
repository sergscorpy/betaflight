# CRUISE

Режим для мультироторів без GPS і компаса. Утримує задані кути pitch/roll;
швидкість, траєкторію та положення не оцінює. Yaw використовує звичайний
контур кутової швидкості прошивки, без окремого збереження курсу.

## Увімкнення й керування

- `CRUISE` — ручне ввімкнення через AUX, постійний ID режиму **59**.
- `CRUISE RESERVE` — примусова робота з резервним газом для тестування,
  постійний ID **60**. Сам по собі CRUISE не вмикає.
- Потрібні armed, акселерометр і вже піднятий після armed газ.
  Режим недоступний для літаків, 3D, Crash Flip і активного Launch Control.
  При активному GPS Rescue, AUTOPILOT або PASSTHRU запит відхиляється.
- При вході захоплюються фактичні кути. При втраті RX під час уже активного
  CRUISE накопичені цілі зберігаються.
- Pitch/roll поза ±5 PWM від `midrc` змінюють ціль зі швидкістю:
  `angle_limit × (setpointRate / maxRcRate) / 2 с`. Rates/expo і згладжування
  беруться з контролера. У центрі стіка ціль залишається незмінною.
- Максимальний загальний нахил — `min(angle_limit, cruise_angle_limit)`.
  Геометрія: `cos(нахил) = cos(roll) × cos(pitch)`.
  Надлишок команди на межі не накопичується.
- При захопленні поза межею спочатку обмежується модуль roll; pitch
  обмежується найбільшим допустимим значенням при цьому roll зі збереженням
  знака. При roll на межі pitch дорівнює нулю.
- ALT HOLD запитується автоматично. За нормального RX газ змінює цільову
  висоту через звичайний механізм ALT HOLD.

## Автоматичне зменшення pitch

Використовується вихід контролера висоти **після компенсації нахилу**:

```text
використання = (команда_газу_PWM − ap_throttle_min)
              / (ap_throttle_max − ap_throttle_min)
```

Якщо використання безперервно перевищує 50% протягом 3 с, модуль pitch
зменшується до нуля зі швидкістю 5°/с. Корекція зупиняється при використанні
≤45%. Roll не змінюється, попередній pitch не відновлюється.
Ручна команда pitch має пріоритет і скидає таймер захисту.
Навмисний набір висоти газом не блокує цю корекцію.

## Втрата й відновлення зв’язку

Для польоту в CRUISE при втраті зв’язку встановити через CLI:

```text
set failsafe_procedure = CRUISE
save
```

Прошивка починає CRUISE при виявленні втрати RX, до передачі резервних
значень `rxfail` стабілізатору. Stage 2 використовує окремий стан CRUISE;
таймер посадки не запускається. Дані `rxfail` не змінюють кути, yaw або
цільову висоту CRUISE. Детектор і таймери відновлення FAILSAFE зберігаються.
KILL і явний disarm зберігають штатну дію. До першого підняття газу CRUISE
не запускається, а штатний вихід через тривало низький газ зберігається.

Після відновлення RX звичайний CRUISE продовжує працювати. Нові команди
стіків дозволяють підлаштовувати його, але вихід відбувається лише при
явній зміні перемикачів режимів польоту. Якщо при виході жоден основний
режим не запитаний, вмикається ANGLE до наступної зміни режиму польоту.
Перемикання біпера та інших допоміжних функцій цього не скасовує.
Після такого виходу утримуваний AUX CRUISE не вмикає режим повторно:
потрібно перемкнути його в OFF, потім ON.

Якщо для FAILSAFE вибрана інша процедура, при втраті RX вже активний
CRUISE утримує цілі під час Stage 1, а Stage 2 виконує вибрану процедуру.

## Резервний стан

За відсутності придатних даних висоти або при ввімкненні `CRUISE RESERVE`
фіксується остання команда колективного газу з добавкою **5% від значення**.
Наприклад, 20% → 21%. Добавка застосовується один раз при вході в резерв,
без повторного множення в кожному циклі. Корекція pitch за газом вимикається.
Утримуються кути й фіксований газ; стіки не змінюють їх до виходу з резерву.

Відновлення RX не спричиняє виходу. Перший придатний набір каналів після
відновлення стає опорним; нова зміна будь-якого з чотирьох каналів
керування більш ніж на 5 PWM спричиняє вихід і передачу керування пілоту.
Статичний газ і невеликий шум у момент відновлення не вважаються новою
командою. У резерв із робочим RX також записується нова опорна позиція
стіків при вході, щоб попереднє налаштування pitch не викликало вихід.

При поверненні придатної висоти ALT HOLD автоматично захоплює **поточну**
висоту й CRUISE повертається до звичайної роботи. Увімкнений примусовий
резерв блокує цей перехід до вимкнення його AUX.

## Налаштування CLI

| Параметр | Типове значення | Одиниці |
|---|---:|---|
| `cruise_angle_limit` | 45 | градуси загального нахилу |
| `cruise_deadband` | 5 | PWM |
| `cruise_throttle_threshold` | 50 | % інтервалу ALT HOLD |
| `cruise_throttle_hysteresis` | 5 | відсоткові пункти |
| `cruise_throttle_delay` | 3000 | мс |
| `cruise_pitch_correction_rate` | 5 | °/с |
| `cruise_reserve_boost` | 5 | % захопленого газу |
| `cruise_stick_time` | 2000 | мс |

Приклад призначення: рядок AUX 2, канал AUX 3, діапазон 1700–2100:

```text
aux 2 59 2 1700 2100 0 0
```

Індекс рядка та AUX у CLI починаються з нуля. Обрати вільний рядок і
потрібний канал; приклад не потрібно копіювати поверх наявного призначення.
ALT HOLD продовжує використовувати власні налаштування та дані оцінювача
висоти. При вході з CRUISE колективний газ використовується для початкової
оцінки газу зависання з урахуванням поточного нахилу; це не окремий
алгоритм навчання тяги чи оцінка напруги батареї.

## Відображення й журнал

OSD: індикатор режиму `CRUI`, повідомлення `CRUISE: ACTIVE`, `RX LOST`,
`RX RESTORED`, `RESERVE`, `ALT RESTORED`, `PITCH REDUCED`, `EXIT`,
`UNAVAILABLE` з префіксом `CRUISE: `. Критичні наявні попередження мають
вищий пріоритет. CRSF передає назву `CRUISE`.

`set debug_mode = CRUISE` додає до Blackbox:

| Канал debug | Значення |
|---:|---|
| 0, 1 | цільові roll, pitch у 0,1° |
| 2, 3 | фактичні roll, pitch у 0,1° |
| 4 | використання інтервалу газу у 0,1% під час контролю ALT HOLD |
| 5 | останній опорний газ ×1000 |
| 6 | резерв: 0/1 |
| 7 | автоматична корекція: 0/1 |

## Перевірка й сумісність конфігурації

Версію групи призначень режимів AUX підвищено згідно з правилом
`rc_modes.h`. Після оновлення прошивки ці призначення потрібно відновити
та перевірити, зокрема ARM. Інші параметри CRUISE мають власну нову групу.
Прошивка не прошивається на контролер автоматично.

Автоматичні перевірки охоплюють захоплення та межі кутів, накопичення,
затримку/гістерезис корекції, ручний пріоритет, резерв, відновлення RX,
переходи FAILSAFE, утримання висоти та передачу цілей у PID.
Це перевірка логіки; польотна перевірка реакції на вітер, батарею та
динаміку конкретного дрона ще потрібна.
